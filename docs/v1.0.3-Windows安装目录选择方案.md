# v1.0.3 更新方案｜安装时选择桌宠放在哪个盘

## 1. v1.0.2 现在装在哪里

**当前版本默认装在 `%LOCALAPPDATA%\nagisa_app`。** 在资源管理器地址栏粘贴这段路径并回车，就能打开。通常对应 `C:\Users\你的用户名\AppData\Local\nagisa_app`。本机已核对以下位置，建议玩家平时通过开始菜单启动。

| 内容 | v1.0.2 的位置 |
| --- | --- |
| 稳定启动入口 | `%LOCALAPPDATA%\nagisa_app\Nagisa Desktop Pet.exe` |
| 本版实际程序 | `%LOCALAPPDATA%\nagisa_app\app-1.0.2\Nagisa Desktop Pet.exe` |
| 养成存档、设置和桌面位置 | 默认在 `%APPDATA%\Nagisa Desktop Pet`，由 Electron 的 `userData` 管理 |

浏览器决定下载的 Setup 文件放在哪里。即使把 v1.0.2 的 Setup 下载到 D 盘再双击，它仍按当前用户的默认位置安装。**v1.0.3 要增加的是双击 Setup 后选择程序安装位置的页面**，这样玩家既可以沿用默认值，也可以把程序放在 D 盘。[Squirrel 安装目录说明](https://github.com/Squirrel/Squirrel.Windows/blob/develop/docs/using/install-process.md)

## 2. 玩家会看到什么

1. 双击 `Nagisa-Desktop-Pet-1.0.3-win-x64-Setup.exe`，直接进入中文的**选择安装位置**页。显示完整目录、所需空间，以及「浏览」「安装」「取消」。旁边提示「这里保存桌宠程序。已有养成进度会从当前 Windows 账户继续读取。」
2. 首次安装预填 `%LOCALAPPDATA%\Programs\Nagisa Desktop Pet`，可直接点「安装」。例如玩家浏览到 `D:\游戏`，应看到最终路径 `D:\游戏\Nagisa Desktop Pet`；如果已经选中了这个专属文件夹，就使用原路径。点安装前，页面上显示的路径必须和最终写入的一致。
3. 从 v1.0.2 来的玩家也能选目录。识别到旧版时显示其位置，并提示「将升级已安装的桌宠，保留你的存档」。若桌宠在运行，提示玩家右击托盘图标选择「退出」，随后可在安装器中重试。
4. 安装成功后显示「启动古河渚桌宠」。后续运行完整安装包时，目录栏默认回填上次的实际位置；玩家可直接原地更新。若主动换盘，先完成新位置安装，再处理旧位置。

## 3. 开发实施

**选型：保留 Electron Forge 打包程序，Windows 安装外壳改用 NSIS。** v1.0.2 的 Squirrel 走当前用户目录下的固定布局。NSIS 的 Modern UI 已提供目录选择页，可以直接做成中文安装向导。继续发一个离线可用的完整 Setup，沿用现有桌宠 logo、开始菜单名称和手动升级方式。[Forge 的 Squirrel 说明](https://www.electronforge.io/config/makers/squirrel.windows) · [NSIS Modern UI](https://nsis.sourceforge.io/Docs/Modern%20UI%202/Readme.html)

| 步骤 | 具体改动 |
| --- | --- |
| 打出同一份桌宠程序 | 从 [Forge 配置](../nagisa-app/forge.config.ts)沿用应用打包、图标和 Windows 辅助程序配置。新增 Windows 发布脚本，先在 `nagisa-app` 中执行 `npm.cmd run package -- --platform=win32 --arch=x64`，再用锁定版本的 NSIS 3 `makensis` 封装产出的完整目录，含 `resources/app.asar` 和 `NagisaDesktopState.exe`。版本从 [package.json](../nagisa-app/package.json)读取，输出到 `out/release/v1.0.3/`。Windows 发布入口只产出本版正式 Setup。 |
| 目录页与图标 | 建议新增 `nagisa-app/installer/windows.nsi`。使用 `MUI_PAGE_DIRECTORY`、简体中文、`RequestExecutionLevel user`，安装及卸载图标使用 [app-icon.ico](../nagisa-app/src/assets/app-icon.ico)。确认安装前检查目标绝对路径、写权限和剩余空间；拒绝盘符根目录、无关非空目录，以及与旧 Squirrel 根目录或用户存档目录相互包含的路径。提示具体原因并允许重新选择。[NSIS 指令参考](https://nsis.sourceforge.io/Docs/Chapter4.html) |
| 系统入口与下次更新 | 安装成功后在当前用户注册表记录安装位置和版本，创建一个开始菜单入口，并登记 Windows「已安装的应用」卸载项。快捷方式目标为所选目录内的 `Nagisa Desktop Pet.exe`。固定安装标识跨版本复用；安装器读取已登记的路径，结合本应用的安装标记判断原地升级。卸载只清理本应用登记的文件、快捷方式和启动项，保留用户存档及玩家后来放入目录的文件。 |
| 登录启动和存档 | [windows-install.ts](../nagisa-app/src/windows-install.ts) 当前通过 `app-版本号` 和 `Update.exe` 识别 Squirrel。为新布局使用实际安装目录内的 EXE；在替换旧程序前读取本应用登录启动项，区分开启、禁用和未登记，安装成功后把原状态迁到新入口，并核对 Windows 设置中显示的状态。继续使用原 `userData`、应用名与存档格式，换盘无需复制或导入养成数据。 |

### 从旧安装器过渡

- **v1.0.0、v1.0.1 便携版。** 退出旧版后直接运行新 Setup。旧的解压目录由玩家管理。若旧便携程序登记过登录启动，同样迁到新入口。
- **v1.0.2 Squirrel 安装版。** 根据当前用户的安装信息、包标识和旧启动器确认旧版本。选择与旧根目录分开的目标；记录旧版位置及启动状态，把新文件完整写到目标并核验，再调用已核实的旧版卸载器。等旧卸载结束后才登记新版的快捷方式、登录启动和卸载项，防止旧卸载器顺手清掉新入口。完成前不自动启动渚。旧卸载失败时保留新旧状态记录并支持重试。
- **v1.0.3 起的原地更新或换盘。** 使用临时目录暂存新文件。原地更新先保留旧程序以便写盘失败时恢复；换盘安装先验证新副本，再切换登记的入口，最后按旧安装清单清理程序文件。取消选目录、目标盘不可写或写入中断时，应能继续使用原版或重开 Setup 完成恢复。重复运行同一版本最终只保留一组有效入口。

## 4. 验收清单

以下均为待测目标。迁移测试使用 [v1.0.2 已发布安装器](https://github.com/WMXhy/Desktop-pet-of-Nagisa-Furukawa/releases/tag/v1.0.2) 和同一 Windows 测试账户。操作前记录币数、好感、背包、缩放、位置及登录启动状态。

| 场景 | 通过标准 |
| --- | --- |
| 首装默认目录 | 普通账户断网，用资源管理器双击 Setup。目录页可见，默认路径可直接安装，无需管理员权限；开始菜单能启动一个桌宠实例。 |
| 自选 D 盘 | 选含中文和空格的可写目标（如 `D:\我的 游戏\Nagisa Desktop Pet`），核对界面最终路径、运行中程序路径和快捷方式目标三者一致；辅助程序和拖动姿势可用。 |
| 不可用目录与取消 | 用只读目录、空间不足的测试卷或无关非空目录测试。页面说明原因，可返回改选；取消后原桌宠可启动，无新增卸载项，无关文件完整。 |
| 三种旧版直接迁移 | v1.0.0 ZIP、v1.0.1 ZIP、v1.0.2 Setup 各自直接升到自选目录。旧存档数值、缩放和位置均一致。Squirrel 迁移后旧卸载项消失，新快捷方式及卸载项各一个。 |
| 记住目录、换盘、失败重试 | 从非默认目录安装的 v1.0.3 再运行 Setup，目录栏显示旧路径。用较高版本号的内部测试包验证原地升级和换盘；模拟新目录写入失败，原版仍可启动。重试后仅有一份有效注册。 |
| 登录启动、卸载重装 | 用原本开启、禁用两组状态实际注销重登，分别只启动一次新版或保持关闭。从 Windows 设置卸载后无失效入口，用户自己放入的文件仍在；换目录重装后养成可继续。 |
