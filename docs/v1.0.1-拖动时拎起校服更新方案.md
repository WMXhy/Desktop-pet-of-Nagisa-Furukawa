# v1.0.1 更新方案｜拖动时拎起渚的校服

基线为 Windows 桌宠 v1.0.0。本次更新的交付物是一个拖动姿势：鼠标拖起渚时，后背的校服被捏起一角，身体悬在下方；向屏幕左边拖，她的脸朝左，向右拖则朝右。松手后，渚在放下的位置继续刚才的事。

## 一、先确定玩家看到什么

| 玩家操作 | 画面和行为 |
| --- | --- |
| 左键按住，还没移动 | 保持原姿势。按住的时长不触发提起。轻点松手仍走原有问候逻辑。 |
| 向左或向右拖过起拖阈值 | 窗口跟随原来的抓取位置移动。后背衣服绷紧成一个三角，头朝移动方向，发梢和双脚向反方向略微滞后。 |
| 先竖直拖，或沿斜线拖 | 纯竖直起拖用中性悬垂图。斜拖时，横向位移足够便转向对应一侧。 |
| 拖到一半停住，仍按着左键 | 继续悬着，保留最近的朝向。原地的细小抖动不会让脸左右来回翻。 |
| 不松手，往反方向拖 | 从转折点算起，反向移动一小段就转头，即使指针还没有回到最初按下的位置。 |
| 松手 | 立即显示此刻应有的待机、进食或活动帧；此次拖动不触发问候和好感奖励。右键仍打开原有菜单。 |

**抓取位置约定。** 玩家仍可从角色身上的任意位置起拖。三角形的尖端是各张图之间对齐的受力点；按住渚的袖口起拖时，继续保留袖口处的鼠标偏移。这样换姿势和转头都不会让整个窗口突然跳到鼠标中央。

**联调时检查受力点。** 将五帧叠放，检查后背衣服尖端的偏差是否在 2 个原图像素以内。放下时可用[待机睁眼图](../nagisa-app/src/assets/idle_blink/000.png)对照人物大小和留白。

**看小图确认轮廓。** 将图片缩到桌宠默认的 256 × 256，在浅色和深色底各看一次。三角形的底边要融进后背，尖端下方画出两条向肩背展开的布褶，让人看得出拎到的是校服。左右两图并排时，单看鼻尖和刘海轮廓就应能分清朝向。这个版本直接用现有动作承接落地，五张图即可覆盖完整交互。

## 三、分步实施

### 1. 在现有窗口拖动判定上接入姿势

入口在 [index.ts](../nagisa-app/src/index.ts) 的 `updateDrag`、`pet:start`、`pet:move`、`pet:finish` 和 `pet:cancel`。v1.0.0 已按屏幕坐标计算从按下点起的距离，严格大于 5 才标记为拖动。继续以主进程这一判定为准，在允许拖动、位置未锁定、角色可见且未穿透时进入提起姿势。保留现有 `dragged` 标记的点击抑制语义，确保锁定位置时大幅拖划也不会变成问候。

给当前手势增加临时朝向。建议用 **6 个屏幕逻辑像素**作为横向转头距离，和「总距离大于 5」的起拖条件分开处理。首次朝向以按下点为基准。朝右时记录到达的最右 X，从该点向左退满 6 才切左；朝左时反向处理。使用事件的 `screenX`，这样缓慢的一像素移动也能累积，窗口移动和屏幕边缘钳制也不会干扰判断。继续由原有 `petBounds` 计算窗口位置。

### 2. 把姿势送到角色窗口，叠在已有动作上

在 [preload.ts](../nagisa-app/src/preload.ts) 和 [pet-api.d.ts](../nagisa-app/src/pet-api.d.ts) 增加可取消订阅的姿势通知。主进程只在进入提起、朝向改变或结束时通知角色窗口，值可用 `hold / left / right / null`。一次快速拖划若只在松手事件才越过阈值，按拖动结束处理即可，避免在放手后补闪一帧。

在 [renderer.ts](../nagisa-app/src/renderer.ts) 的 `Pet` 中导入并预载五张图片，沿用现有同一个 `img` 和指针捕获。保留原来的 `frame` 作为底层动作，最终图片取「当前提起帧，否则取 `frame`」。现有 `play()` 会处理喂食队列、活动动作和部分提示回调，让它按原时间线运行；放下时撤掉提起画面即可显示最新底帧。这样即使渚在被拎着时做完帮工，也能正常记账、显示完成提示。

建议左右两个方向各按 `000 → 001 → 000` 循环，每张约 300 毫秒，换向从新方向的 `000` 开始。中性姿势固定显示单帧。提起动画使用单独的计时器，切向、结束、隐藏及组件卸载时清理；沿用已有帧率设置安排刷新。开启「减少动态效果」后，各方向只显示自己的 `000`，仍可转头。联调时先用三个目录的 `000.png` 核对提起和换向，再接入左右两个目录的 `001.png` 检查摆动。

### 3. 收好手势，再做版本候选包

在主进程统一收尾：正常松手、取消捕获、隐藏角色、开启穿透、拖动中锁定位置或关闭拖动、找回角色及替换存档时，都应清掉当前手势并通知撤下提起画面。渲染器同步释放本次指针状态，使下一次按下可立即重新拖动。正常松手后浏览器还可能发出丢失捕获事件，重复收尾应无副作用。

提起姿势只在本次手势内有效，无需改养成存档版本。沿用 v1.0.0 的位置保存机制。验收通过后，将 `nagisa-app/package.json` 与 `package-lock.json` 中对应的应用版本同步为 `1.0.1`。在 `nagisa-app` 下运行 `npm.cmd run typecheck` 和 `npm.cmd run make -- --platform=win32 --arch=x64`；从 `out/make/zip/win32/x64/` 解压候选 ZIP，再执行下表中的玩家操作。

## 四、验收用例

| 检查项 | 操作 | 通过标准 |
| --- | --- | --- |
| 轻点与拖动的边界 | 空闲时轻点；再长按不动后松开；另测横移 5 和 6 个逻辑像素。用开发输入复现精确距离。 | 5 及以下沿用点击判定；6 像素拖动进入对应姿势，松开不触发问候或增加好感。 |
| 左、右与中性 | 分别从静止开始向左、向右、竖直拖动，再在竖直拖动途中向右转。 | 依次显示左、右、中性，最后中性转右。头向移动方向，背上衣服尖端稳定，脚自然悬空。 |
| 反向与抖动 | 向右走 40 像素，向左退 2，再退 4；停住两秒，然后慢慢继续向左。 | 退 2 时仍朝右，累计退 6 时转左；停住不落地，继续向左无闪烁。 |
| 放手与屏幕边缘 | 从角色中央和靠边处分别起拖，拖到工作区边缘后松手；重启桌宠。 | 起拖、转头时窗口没有跳位；鼠标移出图片仍能正常放手。重启后位置正确，显示当前正常姿势。 |
| 设置与异常中断 | 分别在禁拖、锁定、穿透下尝试拖动。拖动中用快捷键隐藏或找回；开发模式再触发取消捕获。 | 禁止拖动时不进入提起；穿透时点击传给下层窗口。中断后重新显示无悬挂残影，解除限制后可以立即再次拖动。 |
| 动作与进度 | 温习快结束时起拖，按住跨过结束点再放手；另在进食或抱玩偶动画中途短拖一次。 | 拖动期间提起图可见；温习只发一次 3 学习点，记录一条。放下后接上当下动作或待机，食物和玩偶效果不重复触发。 |
| 动效与画质 | 在 100%、150% 角色缩放下分别左右拖；在 12、24、30 帧设置及「减少动态效果」下复测。 | 衣角无白边、身体无裁切、朝向可辨。常规模式轻摆节奏一致，减少动态时稳定显示代表帧。 |
| 候选 ZIP 与旧进度 | 用 v1.0.0 测试存档记录余额、好感、背包和桌面位置；退出旧版，完整解压并启动 v1.0.1 候选包。 | 五张图在打包版均可显示；旧进度和桌面偏好可继续使用，拖动后的新位置能保存。 |

**完成记录。** 在候选包上录一段「轻点 → 向左拖 → 反向拖 → 停住 → 放下」的短视频，再记录源码提交、ZIP 文件名、SHA-256 和上述用例的实测结果。独立对照五张图和这段录像，即可判断下一轮该调的是衣服轮廓、转头灵敏度，还是悬摆节奏。
