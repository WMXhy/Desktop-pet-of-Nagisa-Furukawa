## 3. 把初始值和喂食规则写成可核对的函数

在 `src/care.ts` 写入下面的核心逻辑。好感每日最多增加 12 点，使用本机日期。用 `revision` 标记「玩家点按钮时看到的是哪一版库存」，可以避免同一画面上的重复请求扣掉两个面包。

```ts
export function localDay(now = new Date()) {
  return [now.getFullYear(), String(now.getMonth() + 1).padStart(2, '0'),
    String(now.getDate()).padStart(2, '0')].join('-');
}

export function newCare(day = localDay()) {
  return { version: 1, revision: 0, coins: 30, fullness: 55, energy: 70,
    mood: 60, affection: 0, daily: { day, gained: 0 }, inventory: { bread: 2 } };
}
export type Care = ReturnType<typeof newCare>;
export type FeedResult =
  | { ok: true; state: Care }
  | { ok: false; state: Care; message: string };

export function feedBread(s: Care, revision: number, day = localDay()): FeedResult {
  if (revision !== s.revision) return { ok: false, state: s, message: '库存已更新，请再看一眼。' };
  if (s.inventory.bread < 1) return { ok: false, state: s, message: '背包里的小面包吃完了。' };
  if (s.fullness >= 100) return { ok: false, state: s, message: '渚已经吃饱了。' };
  const gained = s.daily.day === day ? s.daily.gained : 0;
  const add = gained < 12 && s.affection < 300 ? 1 : 0;
  return { ok: true, state: { ...s, revision: s.revision + 1,
    fullness: Math.min(100, s.fullness + 18), affection: s.affection + add,
    daily: { day, gained: gained + add }, inventory: { ...s.inventory, bread: s.inventory.bread - 1 } } };
}
```

**检查点**：新档喂一次，团子币仍为 30，精力仍为 70，心情仍为 60，好感变为 1。将输入饱食设为 95 时只能增加 5；输入饱食为 100 时应返回失败且库存原样。可以直接用内存中的 `newCare()` 构造这些边界，不用改自己的存档。

## 4. 主进程持有唯一存档

把两个文件放在 `app.getPath('userData')` 下，分别命名为 `save.json` 与 `save.backup.json`。原有窗口位置文件是 `pet-position.json`，仅完成前两次开发的用户即使已有位置记录，也应拿到初始 2 个面包。

按下面的顺序实现 `care-store.ts`，为手账提供 `read(): Care` 和 `feed(revision: number): FeedResult` 两个入口：

1. **加载。** 在 `startPet()` 中、创建手账之前初始化存储。主档和备份都不存在才调用 `newCare()` 并首次写盘。读文件用 UTF-8，解析后检查版本、必要字段、整数范围：饱食/精力/心情为 0～100，好感为 0～300，每日好感为 0～12，币数、库存、修订号为非负安全整数，日期是有效的本地日期字符串。
2. **恢复。** 主档缺失或损坏时尝试通过校验的备份，从备份恢复并在手账提示。若两份文件都损坏，保留原文件，在手账显示读取错误并停用喂食。若主档版本高于当前支持版本，提示升级，保留该文件。
3. **提交。** 在主进程内同步执行「读取当前内存 → 调用 `feedBread` → 提交新档 → 替换内存」。规则拒绝就直接返回结果。用 Node 的 `writeFileSync` 把数据写到同目录临时文件，再用 `renameSync` 替换目标。正常提交时先把当前有效内存状态用同样方法备份，再替换主档；恢复时只修复主档。这样损坏内容不会覆盖好备份。
4. **失败。** 捕获写盘异常，返回 `{ ok: false, state: 当前内存, message: '存档写入失败，面包已保留。' }`。只有主档成功替换才修改内存、返回成功。这个小存档只在产生养成操作时写入，拖动和播放动画不会触发养成写盘。
5. **单实例。** 在 `index.ts` 的 `app.whenReady().then(startPet)` 外加条件：取得 `app.requestSingleInstanceLock()` 的实例才进入原启动分支，第二个实例调用 `app.quit()`。这样两个进程不会同时写同一份文件。

**检查点**：先只连上读取接口。在空白测试存档中打开、关闭、再次打开手账，面包始终是 2。手账重建时只读取当前数据，初始补给只随建档发生一次。

## 5. 打通「手账 → 主进程 → 角色」这条路径

**先接手账的 preload。** 当前 `openJournal()` 创建窗口时只有 `sandbox` 等选项。给它的 `webPreferences` 增加 `preload: MAIN_WINDOW_PRELOAD_WEBPACK_ENTRY`，保留现有隔离设置。然后在 `src/pet-api.d.ts` 已有的 `Window.pet` 对象类型中追加：

```ts
readCare(): Promise<import('./care').Care>;
feedBread(revision: number): Promise<import('./care').FeedResult>;
onFed(callback: () => void): () => void;
```

在 `preload.ts` 当前 `exposeInMainWorld('pet', …)` 的同一对象中追加：

```ts
readCare: () => ipcRenderer.invoke('care:read'),
feedBread: revision => ipcRenderer.invoke('care:feed', revision),
onFed: callback => {
  const listener = () => callback();
  ipcRenderer.on('care:fed', listener);
  return () => { ipcRenderer.removeListener('care:fed', listener); };
},
```

**再注册手账专用处理。** 沿用现有的窗口级 IPC。在 `openJournal()` 内创建窗口后、调用 `loadURL` 前注册。以下 `store` 指第 4 节在 `startPet()` 中创建并复用的存储对象。

```ts
const wc = window.webContents;
wc.ipc.handle('care:read', event => {
  if (event.senderFrame !== wc.mainFrame) throw new Error('无效的手账请求');
  return store.read();
});
wc.ipc.handle('care:feed', (event, revision: number) => {
  if (event.senderFrame !== wc.mainFrame || !Number.isSafeInteger(revision))
    throw new Error('无效的喂食请求');
  const result = store.feed(revision);
  if (result.ok && !petWindow.isDestroyed() && petWindow.isVisible())
    petWindow.webContents.send('care:fed');
  return result;
});
```

**最后改 `Journal()`。** 在原有 420 × 320 窗口内，上半部列出团子币、饱食、精力、心情和好感，下半部显示「背包 / 小面包 × 数量」和「喂给渚」按钮。状态区用 `overflow: auto` 或沿用手账现有滚动容器，小窗口也能点到底部按钮。推荐按以下顺序接线：

- 初始化时调用 `window.pet.readCare()`，成功后设置 `state`，加载失败则显示原因和重试入口。恢复备份的提示可作为读取结果的附加通知传到手账，例如独立的只读恢复消息。
- 根据库存和饱食生成按钮说明。正常时显示「饱食 55 → 73」，饱食 95 时显示「95 → 100」；满饱食、无库存及请求处理中禁用按钮，显示对应原因。
- 点击时以当前 `state.revision` 调用 `window.pet.feedBread(...)`，等待期间锁住按钮。返回后用完整的 `result.state` 刷新，成功显示「已喂一个小面包」，失败显示 `result.message`。在 `finally` 中解锁，IPC 异常时重新读取状态再允许重试。
- 关闭手账后重新打开，重新读主进程状态。角色隐藏时，手账的成功提示仍然有效，找回角色后直接回到待机。

## 6. 把进食接入已有动画

在 `renderer.ts` 像导入 `wave0～wave3` 一样导入 `./assets/eat/000.png` 至 `004.png`，分别命名为 `eat0～eat4`。在 `wave` 常量后加入：

```ts
const eat: readonly Frame[] = [
  [eat0, 180], [eat1, 240], [eat2, 220], [eat3, 500], [eat4, 360],
];
```

当前 `Pet()` 里的 `play(frames)` 会接管已有计时器，并在播完后调用 `idle()`。用它直接播 `eat`。将 `bubble` 从布尔改为字符串，初始为空，渲染时显示其文本；原问候路径改为设置“今天也一起加油吧。”，原先清除气泡的地方都改为设置空串。在同一个管理计时器的 `useEffect` 内订阅：

```ts
const unsubscribe = window.pet.onFed(() => {
  if (document.hidden) return;
  waving = true;
  window.clearTimeout(bubbleTimer);
  setBubble('面包好香，谢谢你。');
  bubbleTimer = window.setTimeout(() => setBubble(''), 2500);
  play(eat);
});
```

在原 effect 的清理函数中调用 `unsubscribe()`。此处沿用的 `waving` 实际表示「正在执行交互动作」，建议在本次修改中统一改名为 `playingInteraction`。喂食可打断问候，进食期间轻点不会抢走动画，`idle()` 会恢复交互。

## 7. 验收与复测

从 `nagisa-app` 运行 `npm.cmd run typecheck`，通过后运行 `npm.cmd start`。涉及存档损坏、满饱食等情况，使用独立测试目录：可让开发版在 `app.whenReady()` 之前读取测试用环境变量 `NAGISA_TEST_DATA`，目录已创建且为绝对路径时才调用 `app.setPath('userData', 路径)`。所有测试用例都从表内注明的前置状态开始；手工调整测试 JSON 前完整退出应用。

| 用例 | 怎样做 | 通过标准 |
|---|---|---|
| 第一份面包 | 新测试目录 → 打开手账 → 喂 1 次 | 初始 30 币、饱食 55、精力 70、心情 60、好感 0、面包 2；喂后饱食 73、面包 1、好感 1，其余不变 |
| 存档可续玩 | 完成上项后立刻从托盘退出，重启并重新打开手账 | 读出 73、1、1；再喂一次得到饱食 91、面包 0、好感 2，之后按钮禁用 |
| 重复操作 | 对同一个修订号连续提交两次喂食请求 | 只成功一次，后一个请求返回最新状态；只扣一个面包、只触发一次动画 |
| 接近满值及每日上限 | 测试档设饱食 95、面包 2，当日已得好感 12；喂一次后再点 | 第一次饱食到 100、面包剩 1、好感不变；第二次不能消费。把日记录改为昨天并调低饱食，今天可再获得 1 点 |
| 真实进食动作 | 角色可见时喂食，播放中轻点；再隐藏角色，用新测试档喂食 | 可见时播放 5 帧、显示专用气泡、自动回到眨眼；隐藏时正常扣一次并更新手账 |
| 写盘失败 | 在独立测试目录，先建档，再临时创建名为 `save.json.tmp` 的目录使主档临时文件写入失败 | 提示保存失败，库存和饱食不变，角色不播放成功动作；移走该测试目录项后可重试 |
| 备份恢复 | 初始档连续喂两次，完整退出，把测试主档内容改成无效 JSON，再启动 | 从上一个有效版本恢复为饱食 73、面包 1；提示恢复来源；位置记录正常 |
| 旧功能回归 | 轻点、拖动、穿透、找回、开关手账、从托盘退出 | 问候和喂食各有自己的反馈；只开一个手账窗口，两种存档各自保存 |

**完成线**：数值验收通过后，用正式 6 张图片再走一次「喂食 → 看完整动作 → 退出 → 重开核对」。这时下次开发才有可靠的库存和存档可供活动计时、休息与打工复用。
