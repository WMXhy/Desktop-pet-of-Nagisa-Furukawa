# v1.1.1 更新方案｜在渚的头顶选食物、喂食和补货

**玩家体验。** 轻点渚，再点右侧「喂食」团子，她的头顶就会出现一排食物。想喂一口，左击有库存的食物即可；想知道效果，停留一秒；想补货，右击任意食物。吃完的食物仍摆在原位，左击它也能买。整个过程可以留在桌面上完成。

## 一、按两张草图布置界面

侧面的四个团子保持展开，「喂食」显示选中状态。食物栏以渚的头顶为锚点，购买卡只在需要时叠在食物栏上方。以下以 **30 币、红豆面包库存为 0、选购 2 个**为例：

```text
  ╭─────────────────────────────────────────╮
  │  [食物图]  红豆面包          12 团子币 / 个 │
  │            松软的面包里裹着一层红豆馅。     │
  │  数量 2    0 ───────────●  2（最多）      │
  │  余额 30 币 · 买后剩 6 币    [购买 · 24 币] │
  ╰─────────────────────────────────────────╯
  ╭─────────────────────────────────────────╮
  │     小面包图 ×2   红豆面包图 ×0   团子点心图 ×1 │
  │     ━━━━━━━━━ 横向浏览条 ━━━━━━━━━       │
  ╰─────────────────────────────────────────╯
                      渚                 [喂食]
```

购买卡建议与食物栏等宽。上排左侧直接摆透明食物图，右侧排名称、单价和一句短介绍；下排给数量滑杆留出足够宽度，底部左侧显示余额，右侧放购买按钮。不画草图中的方形占位框。页面有两种可拖动控件：**食物栏底部的横条浏览品类，购买卡内的滑杆选择件数**。数量滑杆标出两端值和当前件数，避免玩家混淆。

## 二、食物栏的操作

| 玩家操作或状态 | 画面与行为 |
| --- | --- |
| 第一次点「喂食」 | 在头顶列出食物目录的所有品类，顺序固定为小面包、红豆面包、团子点心。再次点「喂食」收起食物栏及购买卡。角色右键菜单和手账里的背包、零食店仍可使用。 |
| 查看库存 | 每张图的右下角用可读的小字显示 `×数量`，包括 `×0`。数量为 0 时只降低食物图的饱和度，保留轮廓，数字保持清晰。空库存的格子仍能悬停、左击和右击。 |
| 滚动食物 | 指针位于食物栏时，前后滚动鼠标中间滚轮即可左右浏览；触控板横滑和拖动底部滚动条也可用，三者同步同一滚动位置。无需按住滚轮。所有食物都放得下时，底部条显示完整范围，无需滚动；窄屏或品类增加时可以滚到最后一项。 |
| 指针停在同一食物满 1 秒 | 在该项附近出现轻量提示，展示食物名以及「心情 +N、饱食度 +N、好感 +N」。用当前状态计算实际可增加值，含 +0。零库存也可预览，并提示「已吃完，点击补货」。移出或切换食物、滚动、点击时清除旧提示和计时；新项目重新计满 1 秒。 |
| 左击库存大于 0 的食物 | 直接喂 1 个。成功后播放该食物原有进食反馈、刷新数量，食物栏留在原位。最后一个吃完后图片变灰，本次点击到此结束；下次点击才打开购买卡。渚已吃饱、正在活动或游戏时，显示已有原因并保留库存。 |
| 左击零库存，或右击任意库存 | 在食物栏上方打开该食物的购买卡。右击只触发补货，拦住系统菜单和角色右键菜单。换选另一种食物时原位更新同一张卡，清除旧商品数量和悬停提示。 |

## 三、购买数量、付款与 10 秒收起

1. **定上限。** 每次打开卡都读取最新余额。通常 `Max = floor(当前团子币 ÷ 单价)`，同时沿用现有库存整数上限。滑杆从 0 到 Max，步长 1，买得起时默认 1；右端显示「最多 N」，可直接选满。Max 为 0 时显示「余额不足」或对应库存原因，按钮不可用。玩家主动选到 0 时也不能付款。
2. **先报价，再确认。** 滑杆每变化一格，同步更新件数、总价和购买后余额。30 币买红豆面包时最多 2 个，选 2 个就显示「购买 · 24 币」和「买后剩 6 币」。打开卡、滑动和离开均不扣币。购买提交期间锁住按钮；成功后只加库存，收起购买卡，保留食物栏并让该图恢复彩色。玩家可再左击喂食。
3. **从离开购买卡开始计时。** 指针离开整张卡（包括移到下面的食物栏）后开始 10 秒计时，回来立即取消；再次离开重新计满 10 秒。因点击下方食物而开卡时，指针通常还在卡外，此时从开卡开始计。图片、文字、滑杆、按钮之间移动视为仍在卡内。拖动数量滑杆时保持卡片，释放在卡外再开始计时。超时只收起购买卡，保留食物栏、库存和滚动位置。
4. **主动收起优先。** Esc 依次关闭购买卡、食物栏、团子菜单；点击其他团子转去对应界面。主动点击其他应用、拖动或隐藏桌宠、开启穿透时沿用整组收起规则。单纯把鼠标移出购买卡无需立即收起整个菜单。键盘用户可聚焦食物查看详情、用菜单键打开补货、方向键调整数量；键盘正操作购买卡时暂停自动收起。

## 四、分步实施

1. **把「喂食」改为菜单内展开。** 当前[快捷菜单窗口](../nagisa-app/src/quick-menu-window.ts)收到选项后会先隐藏再跳转。对喂食单独切换食物栏，其余三项沿用原导航。建议在同一个菜单窗口中渲染侧面团子、头顶食物栏、提示与购买卡。扩展[布局计算](../nagisa-app/src/quick-menu-layout.ts)，每次展开或收起都更新窗口边界、控件坐标和 Windows 命中区域；未绘制的空白继续让鼠标点到桌面。头顶放不下整组时优先将购买卡移到食物栏侧方，仍不足则把整组放到角色下方并限制到所在屏幕工作区。切换层级不挪动角色、不改写保存的位置。
2. **复用背包与商店的规则。** 从 [food-art.ts](../nagisa-app/src/food-art.ts) 读取图标，从 `foodIds` 枚举所有品类；不要套用背包隐藏零库存商品的筛选。复用 `previewFood` 计算三项差值，`foodUnavailable` 判定能否喂食，`purchaseUnavailable` 校验购买数量。手账和快捷栏共用[现有喂食与购买处理](../nagisa-app/src/index.ts)，保证库存、扣币、进食动画及存档行为一致。[手账喂食与零食店](../nagisa-app/src/food-panel.ts)
3. **给菜单接入实时库存。** 现有 [preload.ts](../nagisa-app/src/preload.ts) 为快捷菜单单独暴露接口，而手账的喂食和购买命令绑定在手账窗口上。给菜单补上读取、订阅状态、喂一个、购买指定数量四项能力；主进程校验来源窗口、当前菜单会话、食物编号、数量、存档代次和修订号。首次打开用快照填充，随后接受活动结算、手账消费等更新。余额变化时立即重算 Max 并夹紧所选数量。过期请求提示重新确认，失败不自动重提，不提前播放成功动画。
4. **处理输入与计时。** 在[快捷菜单界面](../nagisa-app/src/quick-menu.ts)分别维护食物提示的 1 秒计时与购买卡的 10 秒计时。用商品编号及本次展示标识防止旧回调关掉新卡。切换品类、收起、隐藏、卸载组件时清理对应计时与指针捕获。横向滚动条始终同步真实滚动量；拖动滚动条或数量滑杆后松开，不触发下方食物的点击。

## 五、验收用例

| 场景 | 操作与通过标准 |
| --- | --- |
| 入口与滚动 | 点「喂食」只展开头顶食物栏，四个团子仍在。三种食物包含零库存项。用窄宽度制造溢出，滚轮和拖底部条均能到达最后一项；回到宽布局无多余滚动、无误喂。 |
| 一秒提示 | 在 A 停留 0.8 秒再移到 B，A 不弹，B 满 1 秒才弹。测饱食 95 的小面包和好感已满当日额度两种情形，三项增量与喂食后的实际变化一致。 |
| 左击与右击 | 小面包库存 1，左击后只吃 1 个，显示灰图和 ×0；再左击才开补货。分别右击有货、无货的图，都打开正确商品，余额、好感和库存不变。忙碌时左击有货给出原因，右击仍能查看购买。 |
| 数量与结账 | 30 币、红豆面包库存 0，Max 为 2；选 2 付款一次，余额 6、库存 2，图片恢复彩色，渚未自动进食。再右击该商品，Max 为 0。另测余额恰好等于单价、手动选 0、快速双击购买、打开后余额被手账消费。无负余额、重复扣币或库存误增。 |
| 十秒规则 | 开卡后一直不移入，满 10 秒只收购买卡；再次开卡，移出 9 秒后返回，停在卡内超过 10 秒仍可操作，再移出满 10 秒才关闭。跨子控件、拖动滑杆、切换商品后旧计时都不会提前关卡。 |
| 屏幕与原交互 | 顶边、右上角、负坐标副屏及 100%／150% 缩放下检查三层均可达，滚动条和购买按钮可点击，透明间隙可点到底层。复测 Esc、原右键菜单、拖动、穿透、全屏隐藏、打工、学习和游戏。 |
| 安装版与持久化 | 用 v1.1.0 正式 Setup 的测试档升级；执行一次购买、一次喂食，重启并打开手账。余额、库存、养成数值与操作结果一致，旧存档及桌面位置可续用。 |

按项目现有流程执行 `npm.cmd run typecheck` 和 `npm.cmd run release:windows`。从最终 v1.1.1 安装包复测后，把实际通过的用例、源码提交、安装包大小和 SHA-256 填入[更新记录](更新记录.md)。
