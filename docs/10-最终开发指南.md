# 最终开发指南 · 交付可长期使用的 Windows 本地版

**交付标准**：玩家在一台没有 Node.js 的 Windows x64 电脑上解压 ZIP，启动渚，能从托盘找到设置、调好位置和提醒，完成一次「帮工 → 买面包 → 喂食」。退出再开，养成进度和桌面偏好都保留；换到另一份程序目录后仍能读取原存档。

前九次开发已经覆盖角色、养成、商店、活动、游戏及关系。本轮对应[总方案阶段五](../古河渚桌宠分阶段制作方案.md)，集中完成设置、数据管理和交付验收。API Agent 是否立项由作者未来决定。当前源码、已有产物与验证范围见[项目现状与维护交接](项目现状与维护交接.md)。

## 1. 先做一条能从桌面走通的设置路径

1. 在 [index.ts](../nagisa-app/src/index.ts) 仿照手账窗口创建单例 `openSettings()`。由托盘「设置」打开普通窗口，载入同一渲染入口的 `#settings`；重复点击聚焦已有实例。从手账也能进入。关闭设置后角色继续运行。
2. 增加独立的 `settings.ts`（类型、默认值、字段校验）和 `settings-store.ts`（加载与保存）。在 `userData` 下写入带独立版本号的 `settings.json`。沿用已有 `pet-position.json` 保存坐标，养成仍使用 v6。旧用户第一次启动时补默认偏好，原有进度和位置继续加载。
3. 在 [preload.ts](../nagisa-app/src/preload.ts) 和 [pet-api.d.ts](../nagisa-app/src/pet-api.d.ts) 增加读取、预览、应用、撤销预览、订阅设置变化的窄接口。系统注册和磁盘写入由主进程完成；设置窗口只能发受支持的字段。关闭窗口、点取消都要撤销预览。
4. 先实现一个闭环：「缩放 100% → 拖到 125% → 角色立即放大 → 取消后恢复 → 再设 125% 并应用 → 重启仍是 125%」。稳定后再扩展其余分类。保存使用临时文件替换；系统操作或落盘失败时恢复原有配置，并在具体设置项旁说明原因。
5. 补齐角色右键快捷菜单和初次使用提示。菜单中的喂食、打工、学习、游戏可定位到已有手账分区或现有游戏准备页；领取与扣费仍走原有入口。首次提示只引导一次，可跳过，完成状态记入偏好。穿透开启时由系统托盘找回角色。

## 2. 七页设置怎样实施和验收

默认值以[总方案的设置表](../古河渚桌宠分阶段制作方案.md#三设置界面)为准。窗口左侧列分类，右侧只显示当前分类；每页提供「恢复本页默认」，先预览受影响的项，再由玩家应用。

| 页 | 实施要点 | 亲手验证 |
|---|---|---|
| 常规 | 简体中文；登录启动默认关、启动时显示角色默认开、关闭手账后驻留托盘默认开。登录启动读取系统实际状态；关闭驻留时明确关闭手账会退出桌宠 | 切换开机启动后重新打开设置，核对系统状态。关闭启动显示后用托盘找回 |
| 外观与桌面 | 缩放 50%～200%、透明度 30%～100%、置顶、锁定位置、目标显示器。将当前固定的 256 逻辑像素改为按缩放换算，遵守原屏幕工作区，小游戏位置随新边界计算 | 在 125%/150% 系统缩放下拖至屏幕边缘。拔掉副屏，角色完整回到主屏；锁定后仍可轻点问候 |
| 互动 | 托盘与设置共享同一穿透状态；实现允许拖动、2～10 秒气泡、主动问候默认关、间隔默认 30 分钟。把用户隐藏、免打扰临时隐藏分别记录。熟悉后可用已解锁话题，主动问候不触发每日轻点加分 | 关闭拖动还能问候；打开穿透能点到底层窗口；找回角色后设置状态也更新 |
| 声音与动画 | 总音量默认 50%、交互音效默认关、提供试听。最小实现可用本地生成的短提示音，减少动态效果时用代表帧和文字。12/24/30 帧刷新选项限制绘制，按经过的毫秒数决定当前动作帧 | 音量为 0 时静音；三档下抱玩偶总时长均约 1.6 秒；减少动态效果后商店和游戏仍有完整反馈 |
| 提醒与专注 | 完成气泡默认开、系统通知默认关。统一判断 22:00～08:00 跨午夜安静时段、全屏免打扰及手动设置，再分发声音、主动气泡和系统通知。隐藏不影响主进程结算 | 23:00 与 07:59 安静，08:00 恢复。全屏播放时验证自动抑制，退出全屏后恢复原先的显隐状态；手账仍只有一条完成记录 |
| 快捷键 | 默认不注册全局键，支持显示/隐藏、取消穿透、打开手账。录入时捕获组合键；应用时先检查重复和系统占用，成功后替换，失败保留旧键，退出时注销 | 人为制造一次键位冲突，原键仍可用；清空映射后托盘仍可操作 |
| 存档与隐私 | 显示最近成功保存时间，提供导出、导入预览、恢复备份和清空。数据替换流程见下一节 | 把已有玩偶、学习解锁和关系记录一起导出，导入独立档后逐项对照 |

**全屏判断要检查其他应用。** 主进程可查询 Windows 前台窗口所在显示器及窗口覆盖区域，排除桌面、任务栏和自己的窗口，覆盖该屏幕时触发免打扰。还可在发系统通知前参考 Windows 的通知状态。分别用无边框全屏、播放器全屏和普通最大化窗口测试；实际游戏结算始终走现有运行时。[Windows 通知状态接口](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryusernotificationstate)

## 3. 导入、备份和重置

**导出格式**建议使用带 `exportVersion` 的 JSON，封装已提交的养成状态和玩家可迁移的界面偏好。排除屏幕坐标、系统登录启动注册和本机全局快捷键。导出前让运行时推进已到期活动并取得一致快照，未完成的小游戏按既有规则处理。

**导入顺序**：

1. 读取候选文件，在内存校验导出版本、养成结构及偏好范围，复用 [care-store.ts](../nagisa-app/src/care-store.ts) 的 v1～v6 校验和迁移。显示币数、背包、玩具、学习点、好感与进行中的活动，由玩家确认替换。
2. 执行替换时短暂阻止新的购买、作答和活动命令，清理旧对局并停止旧运行时的到期回调。先保存一份可恢复的导入前快照，再提交新状态及偏好。两文件任一失败时恢复整套旧数据；可用短事务标记在中断后完成回滚。保留已存在的 `save.backup.json`，直到确认候选有效。
3. 从选中的新状态重新建立运行时并广播。当前窗口按完整快照重置，包括清理前一份档的修订号缓存；否则导入低修订号存档后页面可能继续显示旧余额。若导入的是已到期活动，由主进程按实例 ID 结算一次。
4. 「恢复上次备份」同样先校验并预览，先读出选定的备份再写入，避免被当前存档覆盖。「清空养成」展示影响并二次确认，重建初始 30 币、2 个小面包的状态，明确是否保留偏好。测试一律使用独立目录。

## 4. Windows x64 打包

当前 [forge.config.ts](../nagisa-app/forge.config.ts) 使用 Squirrel 生成 Windows 安装包，ZIP maker 的平台列表只有 `darwin`。在原列表保留 macOS 并加入 Windows，即 `new MakerZIP({}, ['darwin', 'win32'])`。沿用已有 ICO、ASAR 和打包脚本。候选包使用与本次源码对应的版本号或提交号记录来源。[Forge ZIP maker](https://www.electronforge.io/config/makers/zip)

在项目根目录运行以下命令。开发验收用的 `NAGISA_TEST_DATA`、`NAGISA_FAST_ACTIVITY` 仅供开发模式；实际打包验收使用正式时长和独立 Windows 测试账户。

```powershell
Set-Location '.\nagisa-app'
# 新检出或依赖不齐时先执行 npm.cmd ci
npm.cmd run typecheck
npm.cmd run make -- --platform=win32 --arch=x64
Get-ChildItem -LiteralPath '.\out\make' -Recurse -Filter '*.zip' |
  Select-Object FullName, Length, LastWriteTime
```

检查本轮生成时间，记录候选 ZIP 的字节数及 SHA-256。把 ZIP 解压到新目录，运行其中的 `Nagisa Desktop Pet.exe`；再用一台没有 Node.js、没有项目源码的 Windows x64 机器离线测试。便携包指可解压运行，养成数据仍保存在当前 Windows 用户的应用数据目录中。发布给其他人前核对所用角色美术、字体与声音的分发授权。

## 5. 最终验收单

每项填写「通过／失败／待实机」及实际结果。已有开发包、源码可读和类型检查都不能替代本轮候选包的实测。

| 场景 | 操作 | 合格结果 |
|---|---|---|
| 首次使用 | 新用户离线解压运行，跳过引导，托盘打开手账和设置，再次双击 exe | 只有一个实例、无白底或空白窗口，角色、菜单、设置都可找回 |
| 养成主线 | 新档用正式时长帮工，退出跨过截止点并重开两次；买 2 个面包，再喂 1 个 | 余额 30 → 48 → 36，库存 2 → 4 → 3；工资只领一次 |
| 学习、游戏与关系 | 用测试档完成第 3 次温习；玩一局猜团子；重试旧作答；从 29 好感做当日首次问候 | 9 学习点解锁戏剧部；旧作答不重复发奖；30 好感只生成一条关系记录 |
| 商店与动画 | 买玩偶并重开，试重复购买；使用玩偶主题，查看亲密待机和减少动态效果 | 玩具只扣一次钱，重启仍能用；切换显示策略不改变游戏收益 |
| 桌面常驻 | 连续运行至少 30 分钟，开关三个面板，切换缩放、穿透、快捷键，断开副屏，睡眠再唤醒 | 无残留窗口或重复计时器，托盘可恢复；休眠不扣离线饱食，定时活动按到期时间结算 |
| 数据恢复 | 导出测试档、导入较低修订号档、恢复备份；另试损坏 JSON、较新版本和写盘失败 | 成功时所有窗口与磁盘一致；失败保留原进度并能重试，半途取消无改动 |
| 更新与发放 | 新版本解压到另一目录，用同一测试账户启动；验证默认关的音效、通知和登录启动 | 原有币数、玩具、关系与偏好沿用，默认不会多弹通知或重复注册启动项 |

**本轮素材**：新增角色或商品 PNG **0 张**。沿用[应用图标](../nagisa-app/src/assets/app-icon.png)和现有动作做设置预览。设置说明用文字和原生控件，试玩时以看得清、点得到、能恢复为准。
