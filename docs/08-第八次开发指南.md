# 第八次开发指南 · 给渚买一只团子玩偶

**本次完成线**：从新档的 30 枚团子币开始，在手账的玩具店花 25 币买下团子玩偶。余额剩 5 币，背包出现一只玩偶，点「抱一抱」能看到渚把它贴到脸边。打开猜团子，选择玩偶主题打一局。退出重开，玩偶仍在，不能重复扣款。第二件玩具是 45 币的小舞台布景，买下后可与渚玩「台词接龙」。

接续[第七次开发指南](07-第七次开发指南.md)。先做玩偶，跑通“购买一次、永久拥有、随时使用”；再用同一条购买流程上架小舞台。免费的基础猜团子继续保留。好感等级事件和亲密待机动作排在后续开发。

## 2. 先做永久购买与存档

在 [care.ts](../nagisa-app/src/care.ts) 定义两件商品：

```ts
export const toys = {
  dangoPlush: { name: '团子玩偶', price: 25 },
  miniStage: { name: '小舞台布景', price: 45 },
} as const;
export type ToyId = keyof typeof toys;
```

建议存储 `ownedToys: Record<ToyId, boolean>`，新档两项均为 `false`。食物库存仍保留数量，玩具持有状态单独保存。持有玩偶也不算“背包里有食物”，避免影响已有应急小面包的领取条件。

1. **升级到 v5。** 在 [care-store.ts](../nagisa-app/src/care-store.ts) 先固定 v4 的类型和校验，再扩展当前版本。v4 已含学习点、三种食品、运行中的活动与历史，复制其完整数据，只补两项未拥有的玩具和新版本号。v1～v3 沿用已有迁移，再补同样字段。v5 读档时校验两项均为布尔值。主档与备份都走同一读取流程，保留较新版本保护和旧档备份。
2. **编写购买函数。** `buyToy(state, id, revision)` 先检查修订号，检查是否已拥有和余额，再返回币数与持有状态同时更新的候选状态。主进程校验 ID，只从本地商品表取价格；不接收数量。成本恰等于余额时允许购买。
3. **沿用提交路径。** 在 [care-runtime.ts](../nagisa-app/src/care-runtime.ts) 通过现有 `apply()` 提交，成功才广播快照；修订号仍由存储层更新。工作或游戏中可买玩具，当前活动和对局继续。重复请求、双击或写盘失败都不能出现“已扣款、未拥有”。
4. **接通手账。** 在 [index.ts](../nagisa-app/src/index.ts) 给手账的 `webContents.ipc` 增加 `care:buy-toy`；在 [preload.ts](../nagisa-app/src/preload.ts) 与 [pet-api.d.ts](../nagisa-app/src/pet-api.d.ts) 同步提供 `buyToy(id, revision)`。沿用现有窗口/主 frame 校验。购买失败返回最新状态或可读原因。

核心交易可写成下面这样。它使用升级后的 `Care` 和现有的 `CareResult`，调用前先校验外部传入的 ID。

```ts
export function buyToy(state: Care, id: ToyId, revision: number): CareResult {
  if (revision !== state.revision) return { ok: false, state, message: '余额已更新，请重新确认。' };
  if (state.ownedToys[id]) return { ok: false, state, message: '这件玩具已经在背包里了。' };
  const { price } = toys[id];
  if (state.coins < price) return { ok: false, state, message: '团子币不足。' };
  return { ok: true, state: { ...state, coins: state.coins - price,
    ownedToys: { ...state.ownedToys, [id]: true } } };
}
```

## 3. 手账里的店铺、背包和抱玩偶动作

在 [renderer.ts](../nagisa-app/src/renderer.ts) 的 `Journal()` 中，现有 `shopOpen` 布尔值只能切换手账与零食店。改成 `'journal' | 'snacks' | 'toys'` 三个页面，保留零食店原入口和现有 `submit()` 请求锁。

| 位置 | 具体显示与操作 |
|---|---|
| 玩具店 | 每行展示图标、永久用途、价格和余额预览，例如「团子玩偶 · 25 币，买后剩 5 币」。未拥有才显示购买按钮。成交后留在本页，显示「已拥有」和「现在一起玩」；点击后打开对应准备页 |
| 手账背包 | 在食物区下面列出已拥有的玩具。玩偶提供「抱一抱」「玩偶主题猜团子」，布景提供「台词接龙」。关闭并重开手账后从主进程快照恢复 |
| 角色窗口 | 手账请求抱玩偶时，主进程检查已购买、角色可见、空闲且无正在进行的游戏，再发送一次动作事件。忙碌时解释何时可用，隐藏时提示先从托盘找回角色。角色端避免重复点击叠加播放，1.6 秒后回到当前姿势 |

建议把「抱一抱」定义为纯互动：不消耗玩偶或精力，不额外增加好感，也无需每次写盘。这样玩家可以重看动作，养成奖励仍由已定义的活动和游戏统一发放。

## 4. 给现有猜团子接上玩偶主题

1. 在 [dango.ts](../nagisa-app/src/dango.ts) 的开局参数与 `DangoPreview` 增加模式字段，例如 `'classic' | 'plush' | 'lines'`。未传模式的旧入口按 `classic` 处理。主题在开局成功后固定到当前局号；购买或刷新快照不会在观察途中替换图案。
2. 在 [dango-panel.ts](../nagisa-app/src/dango-panel.ts) 的准备页显示「基础团子」和「团子玩偶」。基础版恒可选，玩偶版需要 `ownedToys.dangoPlush`。从玩具店点「现在一起玩」时预选相应模式，打开准备页免费；若游戏窗口已有进行中的对局，只聚焦现有窗口。
3. `startDango` 在扣精力前再次验证权限。玩偶版沿用已有的三个位置、观察时长和盖碗流程，只把目标图片替换为 `plush_target.png`。开局仍扣 3 精力，猜对心情最多 +5，猜错最多 +3，完成一局好感最多 +1。
4. 继续复用已有的窗口归属、局号、重复作答检查、写盘失败重试与 `gameBusy`。准备页选主题不写入存档；重启后根据永久持有状态重新开放选项。

## 5. 用小舞台布景玩台词接龙

**建议首版采用“一句提示、三个候选、选一句接完”的形式**。这是一种新的题面，沿用现有一局一次选择的结算。建议每局也扣 3 精力、答对心情最多 +5、答错最多 +3、完成好感最多 +1；这组数值是本指南的实现选择，便于两个主题复用同一套奖励规则。

- **先做一条可验证的题。** 为避免三个句子都能接通，给提示一个明确的排练指令。例如题面“台本提示：邀请同伴明天继续排练。”，正确选项“明天放学后，也在这里见面吧。”，另外两项“我把道具放回箱子里。”“今晚的幕布已经收好了。”。正式试玩再补两条原创题，分别围绕开场欢迎和落幕致谢；每题保存稳定 ID、提示、三个选项、正确项 ID。
- **主进程出题。** `startDango` 收到 `lines` 时确认拥有 `miniStage`，再检查空闲与精力。选题、打乱选项，保存本局的正确位置。扩展现有预览/结果类型为按模式区分的数据：猜团子发目标位置用于观察，接龙发题干与排列后的选项，等提交后才回传正确答案。索引仍用 `0 | 1 | 2`，不接受渲染器自报“答对”。
- **给文字题独立的画面。** 现有面板的观察、盖碗阶段用于记忆题。接龙开局即显示小舞台图标、提示和三个可选句子，主进程也把本局允许作答的时间设为题面就绪时，避免点了文字却被盖碗计时拒绝。答完同时标出所选句和正确句。使用[现有朗读排练帧](../nagisa-app/src/assets/rehearse/001.png)配出题，文字单独排版。
- **沿用一份对局状态。** 所有模式共用当前 session 与 `pickDango/leaveDango`。在结算事件内带上模式，让角色区分“团子找到了”和“这句接得真好”。答题中关窗按中途退出处理；完成、回执丢失、重复点选和重新进入均按第七次的同一规则处理。

## 6. 试玩与验收

从项目根目录运行下列命令。用原有独立测试目录开关保护日常存档；同一场景重启时只需再运行 `npm.cmd start`，保留当前目录和环境变量。

```powershell
Set-Location '.\nagisa-app'
$env:NAGISA_TEST_DATA = Join-Path $env:TEMP ('nagisa-toys-' + [guid]::NewGuid().ToString('N'))
npm.cmd run typecheck
npm.cmd start
```

| 用例 | 操作 | 通过标准 |
|---|---|---|
| 首购与重启 | 新档 30 币购买玩偶，关闭手账、退出重开，再尝试购买 | 余额始终是 5，背包只有一只，重启后仍能抱与选玩偶主题 |
| 两种价格边界 | 24 币买玩偶；25 币再买。另用 44、45 币测试布景 | 差 1 币拒绝；刚好够时买后余额 0。两件玩具的持有状态互相独立 |
| 真实获取布景 | 独立新档先帮工一次从 30 到 48，再买 45 币布景 | 余额 3，台词接龙开放，基础猜团子可玩，玩偶主题仍未解锁 |
| 重复与写盘失败 | 双击购买、用旧修订号重发；再用第四次指南的临时文件冲突法阻止一次写盘 | 只有一次有效扣款；写盘失败时不显示已拥有，不开放入口，恢复可写后可重试 |
| 抱玩偶与图像 | 空闲时连续点两次「抱一抱」，随后隐藏再找回 | 动作完整、不叠播；币数、精力、好感不变。商店、怀里和游戏目标的玩偶外观一致 |
| 开局权限与基础版 | 新档直接请求玩偶主题或接龙，再玩一次免费基础版；买玩偶后再玩主题版 | 未拥有时拒绝且不扣精力。基础版仍有花纹团子，主题版只有目标变成玩偶，三只小碗均能完全遮盖目标 |
| 接龙结算与退出 | 用已购布景、精力 70、心情 60、好感 0 的档答对第一题，再开一局答错 | 未触及自然恢复或好感上限时，两局依次得到 67/65/1 和 64/68/2；重复提交不再发奖。第三局关窗只扣启动精力 |
| 旧档回归 | 用 v4 档（已有学习点、三种库存、未完成活动）升级；有玩具但三种食物为 0、饱食 14、余额 5 时领取应急补给 | 升级后两件玩具未拥有，原活动按原奖励结算一次，库存和解锁保留；持有玩具仍可领取符合条件的应急面包 |

**完成后留给下一次开发的入口**：手账已经能读永久权益、角色能响应解锁后的互动。好感等级事件可以沿用这些入口；本次先以两件玩具的购买、使用和重启验收作为完成标准。
