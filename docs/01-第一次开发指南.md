# 第一次开发指南 · 让古河渚出现在 Windows 桌面

**今天做完后的体验**：在 PowerShell 里启动应用，渚出现在主屏右下角，周围能看到桌面壁纸。按住她拖到另一个角落，松手后停在原地。右击系统托盘里的图标，选择“退出桌宠”，角色和图标一起消失。

这对应[总方案第七章的第 1 次开发](../古河渚桌宠分阶段制作方案.md#七第一周可以直接照着做的顺序)。本次用一张静态 PNG 跑通 **Electron 窗口 → React 显示 → 原生拖动 → 托盘退出**。眨眼、轻点问候和位置记忆排在第 2 次开发。

## 1. 建立工程，先验证开发环境

打开 Windows PowerShell，在项目根目录执行下列命令。开发机需要已安装 Git 和受 Electron Forge 支持的 Node.js LTS（自带 npm）。前三条版本查询都应输出版本号；若提示找不到命令，先安装对应工具，重新打开 PowerShell。以下使用 npm 和 npx 的 Windows 命令入口。

```powershell
Set-Location 'E:\Project\desktop-pet'
node --version
npm.cmd --version
git --version
Test-Path -LiteralPath '.\picture\阶段一\idle_blink\000.png'
```

最后一行应返回 `True`。这张现有图片是 512 × 512 的 PNG，带透明通道，后面会以 256 × 256 逻辑像素显示。

在根目录创建名为 `nagisa-app` 的应用子目录，保留现有的文档和素材目录。下面的初始化命令只需执行一次；以后从 `nagisa-app` 目录运行启动命令即可。[Forge 官方模板](https://www.electronforge.io/templates/typescript-+-webpack-template)

```powershell
npx.cmd create-electron-app@latest nagisa-app --template=webpack-typescript
Set-Location '.\nagisa-app'
npm.cmd start
```

**检查点**：看到 Forge 模板的欢迎窗口。关闭窗口，在运行命令的终端按 Ctrl+C 结束可能仍在运行的开发服务，等 PowerShell 提示符出现再继续。若这一步失败，先看终端第一条安装或编译错误，此时尚未接入角色素材。

## 2. 接入 React 和第一张角色图

以下命令均从 `E:\Project\desktop-pet\nagisa-app` 执行。

```powershell
npm.cmd install react react-dom
npm.cmd install -D @types/react @types/react-dom
New-Item -ItemType Directory -Force -Path '.\src\assets' | Out-Null
Copy-Item -LiteralPath '..\picture\阶段一\idle_blink\000.png' -Destination '.\src\assets\nagisa-idle.png'
```

下面的文件路径均相对于 `nagisa-app`。在模板的 `webpack.rules.ts` 中，找到导出的 `rules` 数组，**在数组内新增一项**，保留原有 TypeScript 等规则。若模板已有匹配 PNG 的规则，将该规则对 PNG 的处理改成下面的类型，避免同一图片被处理两遍。

```ts
{ test: /\.png$/i, type: 'asset/inline' },
```

这使主进程和渲染进程导入 PNG 时都得到图片的数据 URL。第一次开发只用这一张图，角色和托盘共用它。新建 `src/images.d.ts`，声明图片导入的类型。

```ts
declare module '*.png' {
  const dataUrl: string;
  export default dataUrl;
}
```

## 3. 主进程创建透明窗口与托盘

在 `webpack.main.config.ts` 中查看 `entry` 指向的主进程文件，通常是 `src/index.ts`。将该入口内容替换为下列代码。模板生成的 Forge 配置和 preload 文件继续使用。这里的两个入口常量由 Forge 的 `main_window` 配置提供。[Forge Webpack 入口说明](https://www.electronforge.io/config/plugins/webpack)

```ts
import { app, BrowserWindow, Menu, nativeImage, screen, Tray } from 'electron';
import petImage from './assets/nagisa-idle.png';

declare const MAIN_WINDOW_WEBPACK_ENTRY: string;
declare const MAIN_WINDOW_PRELOAD_WEBPACK_ENTRY: string;

// 保留对象引用，确保窗口和托盘图标在应用运行期间一直存在。
let petWindow: BrowserWindow;
let tray: Tray;

app.whenReady().then(async () => {
  const area = screen.getPrimaryDisplay().workArea;
  const size = 256;
  const margin = 24;
  petWindow = new BrowserWindow({
    title: '古河渚桌宠',
    width: size,
    height: size,
    x: area.x + area.width - size - margin,
    y: area.y + area.height - size - margin,
    frame: false,
    transparent: true,
    backgroundColor: '#00000000',
    hasShadow: false,
    resizable: false,
    alwaysOnTop: true,
    skipTaskbar: true,
    show: false,
    webPreferences: {
      preload: MAIN_WINDOW_PRELOAD_WEBPACK_ENTRY,
      contextIsolation: true,
      nodeIntegration: false,
      sandbox: true,
    },
  });

  const icon = nativeImage.createFromDataURL(petImage).resize({ width: 32, height: 32 });
  tray = new Tray(icon);
  tray.setToolTip('古河渚桌宠');
  tray.setContextMenu(Menu.buildFromTemplate([
    { label: '退出桌宠', click: () => app.quit() },
  ]));

  await petWindow.loadURL(MAIN_WINDOW_WEBPACK_ENTRY);
  petWindow.showInactive();
}).catch((error) => {
  console.error('桌宠启动失败', error);
  app.quit();
});

app.on('window-all-closed', () => app.quit());
```

这里用主屏的工作区计算位置，给任务栏留出空间。`showInactive()` 让角色出现时保留当前应用的输入焦点。这个版本所有交互都能用 Electron 自身和 CSS 完成，无需向页面开放文件读写或 IPC。

## 4. 渲染进程显示角色并支持拖动

先在 `forge.config.ts` 的 `renderer.entryPoints` 中确认 `html` 和 `js` 指向的文件。模板通常使用以下路径。编辑它们对应的实际文件。

**在 `src/index.html` 中**，保留模板的 `head`，将 `body` 替换为以下内容。如果模板设置了内容安全策略，确保 `img-src` 包含 `'self' data:`，使内联的角色 PNG 可以显示。

```html
<body>
  <div id="root"></div>
</body>
```

**将 `src/renderer.ts` 替换为以下内容**。这里用 React 的 `createElement` 渲染单张图片，可以直接沿用模板的 `.ts` 入口。

```ts
import { createElement } from 'react';
import { createRoot } from 'react-dom/client';
import petImage from './assets/nagisa-idle.png';
import './index.css';

const container = document.getElementById('root');
if (!container) throw new Error('页面缺少 root 容器');

createRoot(container).render(createElement('img', {
  className: 'pet',
  src: petImage,
  alt: '古河渚',
  draggable: false,
}));
```

**将 `src/index.css` 替换为以下内容**。主窗口和页面都需要透明；清除模板自带的边距，角色才能完整占据窗口。

```css
html, body, #root {
  width: 100%;
  height: 100%;
  margin: 0;
  padding: 0;
  background: transparent;
  overflow: hidden;
}

.pet {
  display: block;
  width: 100%;
  height: 100%;
  object-fit: contain;
  user-select: none;
  -webkit-app-region: drag;
  app-region: drag;
}
```

现在按住角色图片即可让 Windows 拖动整个窗口。拖动区域按图片的矩形边界计算，并会接管鼠标点击。第 2 次开发加轻点问候时，要把这一区域的原生拖动替换为按指针位移区分点击和拖动的交互，否则角色收不到点击事件。[Electron 拖动区域说明](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)

## 5. 启动与验收

保存文件，在 `nagisa-app` 目录运行 `npm.cmd start`。主进程或 Webpack 配置改动后，结束上一轮开发进程再启动。按顺序检查，四项都通过即可结束本次开发。

| 检查项 | 怎么操作 | 通过标准 |
|---|---|---|
| 冷启动与显示 | 启动前打开记事本并输入文字，启动桌宠后观察主屏右下角 | 出现一个渚的角色，四肢和头发完整，周围透出原桌面；没有标题栏、白色底板或模板欢迎文字 |
| 原生拖动 | 按住角色身体，拖到屏幕另一角，松开鼠标并继续移动指针 | 整个角色随鼠标移动，松手即停；看不到浏览器拖图片时的半透明副本 |
| 桌面与托盘 | 让普通窗口经过角色所在位置，再打开任务栏通知区域及其折叠菜单 | 角色保持置顶；托盘能找到提示为“古河渚桌宠”的图标，右键能看到“退出桌宠” |
| 退出与重开 | 从托盘选择退出，再启动一次；若 Forge 开发服务仍占用终端，先按 Ctrl+C | 第一次的角色与托盘图标均消失；再次启动只出现一个角色，从主屏右下角开始 |

### 常见卡点

| 现象 | 优先检查 |
|---|---|
| 托盘出现，桌面看不到角色 | 检查渲染入口、`root` 容器及图片导入。临时在 `loadURL` 后加 `petWindow.webContents.openDevTools({ mode: 'detach' })`，看 Console 是否有渲染异常或 `img-src` 拦截；排查后移除该行。 |
| 图片周围出现白方块 | 核对主窗口的 `transparent`、页面三层背景和实际复制的文件。项目里的 `R.jpg` 是另一份素材，示例使用 `idle_blink/000.png`。 |
| 编译提示找不到 PNG 模块 | 检查图片是否在 `src/assets`、声明文件是否为 `src/images.d.ts`，以及 PNG 规则是否已加到主进程和渲染进程共用的规则数组；改配置后重启。 |
| 看到角色却拖不动 | 检查入口是否导入 `index.css`、图片是否有 `pet` 类、`draggable` 是否为 `false`，以及是否有其他元素盖在图片上。 |

完成记录可以只写一行：日期、Windows 版本、显示缩放、通过项数、遗留现象。下一次从“记住拖动后的位置”开始，直接复用已经验证过的窗口和角色图。
