# 第七次开发指南 · 和渚玩一局猜团子

**本次完成线**：打开手账，点「和渚玩猜团子」。在渚身旁的小面板里看一眼三颗团子，记住有花纹的那颗。小碗盖上后，选中它所在的位置。新档从精力 70、心情 60、好感 0 开始，猜中一局后应是 **67、65、1**；若第一局猜错，则是 **67、63、1**。退出重开，已经结算的数值保留。

接续[第六次开发指南](06-第六次开发指南.md)。本次做总方案阶段四的**免费基础版**。零团子币、零学习点、没有玩具也能进入；唯一的数值门槛是精力至少 3。玩偶主题、抱玩偶动作和台词接龙留到玩具商店开发时接入。

## 2. 一局具体怎么玩

| 阶段 | 玩家看到什么 | 程序要做什么 |
|---|---|---|
| 准备 | 三个空位、规则和「开始 · 精力 −3」按钮 | 打开面板免费；按开始才检查精力与活动状态并扣费 |
| 看团子 | 三个位置同时展示，恰好一个有花纹 | 主进程随机选左、中、右之一。建议观察 3 秒，此时禁止作答 |
| 盖碗与选择 | 三只同款小碗覆盖原位置，玩家选择左、中或右 | 基础版保持位置不变。盖碗动画建议 300 毫秒，结束后才接受一次选择 |
| 揭晓 | 抬起碗，标出「你选的」与「花纹团子」，显示实际所得 | 猜中累计心情 +5，猜错 +3；完成一局好感最多 +1，按原有日限与总上限计算 |
| 再来一局或退出 | 有足够精力时可再玩，关闭面板回到桌面 | 每次新局重新随机、分配新局号并扣 3 精力。揭晓后的关闭不影响收益 |

**节奏约定**：按总方案以约 20 秒一局作为体验目标。选择阶段允许玩家想久一点，无人操作不会自动猜错或发奖。点击退出、关掉游戏窗口、程序重启前尚未提交答案，都按中途退出处理：启动时付出的精力保留，心情和好感不变。

## 3. 沿用 v4 存档，把游戏与离线活动分开处理

当前 [care.ts](../nagisa-app/src/care.ts) 的五种 `ActivityKind` 都由截止时间自动结算。猜团子必须等玩家作答。建议让主进程只在**内存**中保留当前局号、目标位置、允许选择的时间及已提交的选择；继续用现有 v4 存档保存精力、心情和好感。这样重启自然结束未完成对局，旧档也不用迁移。

1. **开局**：在 [care-runtime.ts](../nagisa-app/src/care-runtime.ts) 复用 `apply()`。先处理到期活动与自然变化，再检查当前修订号、没有正在进行的活动或游戏、精力 ≥3。用主进程生成的 `randomUUID()` 作局号、`randomInt(3)` 作目标位置（来自 `node:crypto`）。扣 3 精力并提交成功后才让面板进入观察阶段；写入失败时可以原价重试。
2. **作答**：只接收 `roundId` 与玩家选的 `0 | 1 | 2`。主进程核对局号、位置和允许作答的时间，再用自己保存的目标判定对错。将第一次有效选择固定下来；保存失败时允许重试该选择。保留最近一局成功结果，重复到达的同局请求返回原结果，不再次改数值。正常购物或自然变化可能改变修订号，作答应使用该局 ID 并从最新养成状态计算。
3. **退出**：中途退出只清理该局，不退精力；旧窗口带来的退出请求不能清除新局。已提交成功后再关闭，保留奖励。重启后内存没有当前局，禁止恢复画面后补发奖励。
4. **活动互斥**：有游戏时禁止开始休息、学习、打工与喂食；已有定时活动时禁止开局。手账可继续查看与购物。把 `gameBusy` 加到运行时快照供界面禁用按钮，主进程入口也做相同检查。游戏中饱食继续按在线时间变化，空闲精力恢复暂停。在 `sample()` 中按当前局是否存在决定是否累计 `idleMs`，切换开始、作答、退出之前先采样到该时刻。
5. **发布顺序**：现有 `commit()` 写盘成功就广播快照。给运行时内部提交增加一个小的“写入成功后、广播前”回调，在这里设置或清理当前局并缓存结果，保证快照里的 `gameBusy` 与数值同步。退出未完成局只需要释放内存状态并推送更新。角色表情也只在成功结算时通知一次。

在 `care.ts` 里可将收益计算写成下面的纯函数，沿用同一文件已有的 `gainAffection()`。将 `actual` 用于结果文案，可避免心情 99 时仍显示“+5”。

```ts
export function finishDango(state: Care, correct: boolean, day = localDay()) {
  const mood = Math.min(100, state.mood + (correct ? 5 : 3));
  const affectionChange = gainAffection(state, 1, day);
  const next = { ...state, ...affectionChange, mood };
  return {
    state: next,
    actual: { mood: mood - state.mood, affection: next.affection - state.affection },
  };
}
```

在运行时确认该局可结算后，再在 `apply()` 的操作函数内计算并返回 `{ ok: true, state: next }`；实际结果随成功回执交给小游戏。失败时保留旧状态与原选择，不播放成功反馈。

## 4. 面板放在角色旁，手账里提供入口

| 文件 | 具体改动 |
|---|---|
| [index.ts](../nagisa-app/src/index.ts) | 参考 `openJournal()` 建立单例 `openDangoGame()`。由手账「小游戏 → 猜团子」主动打开一个约 320 × 250 的普通窗口，沿用已配置的 preload 与隔离选项，加载同一入口加 `#dango-game`。先尝试角色右侧，放不下改左侧，最后把坐标限制在当前显示器工作区。重复打开聚焦已有面板。 |
| [preload.ts](../nagisa-app/src/preload.ts)、[pet-api.d.ts](../nagisa-app/src/pet-api.d.ts) | 同步声明 `openDangoGame()`、`startDango(revision)`、`pickDango(roundId, slot)`、`leaveDango(roundId)`。手账窗口注册打开面板处理；游戏窗口注册读取快照、开局、选择与退出处理，校验发送窗口及主 frame。 |
| 新建 `src/dango-panel.ts` | 实现 `ready → preview → choose → result` 四个可见状态，错误提示留在当前步骤。用一个循环渲染三处位置，每处使用原生按钮，让键盘 Tab、Enter 也能完成游戏。遮盖后按钮分别叫“选左边”“选中间”“选右边”。 |
| [renderer.ts](../nagisa-app/src/renderer.ts) | 在现有手账与角色分流处显式处理 `#dango-game`。手账显示入口、精力和禁用原因；游戏面板订阅最新养成快照，首次读取成功才允许开始。角色复用现有 `interact()` 显示微笑或鼓励气泡，隐藏期间保留数值变化。 |
| [index.css](../nagisa-app/src/index.css) | 游戏面板使用独立样式：三个等宽位置、三张等大的图、选择后清晰区分结果。动画期间禁用选择；减少动态效果时用直接切换显示相同结果。 |

**两个容易漏掉的细节**：

- `index.ts` 目前只把 `care:changed` 发给角色和手账。游戏窗口也要接收；覆盖现有渲染器读取失败时构造的默认快照。只有开局或合法作答成功回执才能推进游戏画面，普通快照刷新不能重抽目标。作答按钮等待回执时立即禁用。
- 打开面板时先呈现准备页，等待页面就绪再开始扣精力。用户关闭游戏窗口、渲染进程退出或重载时，主进程按所属窗口及局号释放未完成对局。关闭**手账**不应结束仍打开的小游戏。程序退出仍沿用现有在线余数保存逻辑。

## 5. 试玩验收

在项目根目录运行下面的命令，用独立测试档从精力 70、心情 60、好感 0 开始。小游戏不依赖现有的活动快速模式。

```powershell
Set-Location '.\nagisa-app'
$env:NAGISA_TEST_DATA = Join-Path $env:TEMP ('nagisa-dango-' + [guid]::NewGuid().ToString('N'))
npm.cmd run typecheck
npm.cmd start
```

| 用例 | 怎样操作 | 通过标准 |
|---|---|---|
| 不需要玩具 | 新档打开小游戏面板，先关掉；再打开并开始 | 开关准备页后仍为 70 精力；点开始后变为 67。币数和背包不变 |
| 猜中与猜错 | 首局记住花纹位置并选中；接着再开一局故意选错 | 首局结算为精力 67、心情 65、好感 1；紧接第二局结果为 64、68、2。学习点不变 |
| 时序与重复点击 | 观察期点击；可选后双击；用同一局号重复提交；下一局再发旧局号 | 观察期无结果；一局只结算一次；旧局号不能改变当前局 |
| 退出与断开 | 开局后不作答，分别试关面板、退出整个程序、重启 | 相对开局前只少 3 精力；无心情及好感奖励，能重新开局、学习或帮工 |
| 互斥与门槛 | 精力 2 时开始；已有学习活动时开始；游戏中尝试开工和购物 | 前两种均不扣精力；对局中开工被拒绝、购物可用。另测精力恰好 3 时可开局并降到 0 |
| 实际收益 | 独立档将心情设为 99、当日已获好感 12，猜中一局 | 心情变 100，好感不变，结果显示实际 +1 心情、+0 好感或“今日好感已满” |
| 空闲计时 | 在测试档中让空闲恢复余数接近 5 分钟，在进入对局前留足几秒操作时间；留在选择页跨过该阈值 | 游戏期间不恢复空闲精力；退出后接着累计先前的空闲余数 |
| 写盘失败 | 在独立测试档分别阻止开局、作答时替换主档，再恢复可写并重试 | 开局失败不扣精力；作答失败不揭晓、不发奖；恢复后只结算同一选择一次 |
| 桌面和素材 | 移动角色到屏幕边缘再打开面板；观察三个位置，在浅色和深色背景各玩一局 | 面板完整可见、不重复打开，三个碗都能完整遮盖团子；结果表情和文字与实际选择一致 |
| 旧档回归 | 用第六次开发的 v4 档启动，玩一局再重开，并复测学习、零食购买和喂食 | 原学习点、解锁和库存保留；游戏结算数值已保存，原玩法可用 |

**本次验收边界**：免费基础版在三个位置上完整走通两次（一对一错），并通过退出、重开和重复作答检查，就可以进入下一次的永久玩具与主题外观开发。
