# v1.1.0 更新方案｜轻点渚，展开四个团子

**目标体验。** 轻点桌面上的渚，四个扁圆小团子在她右手边（画面右侧）竖排出现，从上到下是「喂食」「打工」「学习」「游戏」。玩家点哪个，就进入哪个界面。比如想让渚温习功课，只需轻点渚、点「学习」，就能看到温习所需时间和开始按钮，再决定是否开始。

## 一、四个团子分别打开哪里

| 从上到下 | 建议外观 | 点击后的第一屏 | 现有入口 |
| --- | --- | --- | --- |
| 喂食 | 蜜桃粉团子，写「喂食」 | 手账滚动到背包，看得到持有的零食和「喂给渚」按钮。背包空时也能进入。 | `openJournal('feed')` |
| 打工 | 烤面包色团子，写「打工」 | 手账定位到「面包店帮工」，可查看报酬与开始条件。 | `openJournal('bakery')` |
| 学习 | 抹茶绿团子，写「学习」 | 手账定位到「温习功课」，可查看耗时和学习点。 | `openJournal('study')` |
| 游戏 | 淡紫色团子，写「游戏」 | 打开「猜团子」小游戏窗口；若已有一局进行中，回到该窗口继续。 | `openDangoGame()` |

打工和学习共用手账活动区，但要定位到各自选项。已有活动时，手账会隐藏可选活动，此时沿用现有逻辑，展示正在进行的活动与剩余时间。**点击团子只负责导航**；消耗食物、开始活动、开始一局游戏，仍由目标界面里的按钮确认。四项与角色右键菜单共用入口。[现有窗口与菜单](../nagisa-app/src/index.ts) · [手账定位逻辑](../nagisa-app/src/renderer.ts)

## 二、点击、拖动和收起

| 操作 | 预期表现 |
| --- | --- |
| 菜单收起时，左键轻点渚 | 松开后展开四个团子，同时沿用原有轻点问候及每日好感规则。即使今天已经问候、问候冷却中或渚正忙，仍可展开菜单。 |
| 展开后再次轻点渚 | 收起菜单。这一次只收起，不再请求问候。点击团子本身也不触发角色问候。 |
| 按住渚并拖动 | 沿用现有起拖阈值和拎校服姿势；一旦开始拖动便收起菜单，放手后保持收起。锁定位置时，真正的轻点仍能打开菜单。 |
| 选择团子、按 Esc 或点击其他窗口 | 选中后收起并打开目标窗口；按 Esc 或点击桌面其他应用时仅收起。点击外部应用的这一下正常传给它。 |
| 右键、隐藏、找回、穿透或全屏隐藏 | 先收起菜单，再执行原行为。角色恢复显示后，等待下一次轻点再展开。 |

## 三、布局与素材

- **对照草图排版。** 始终为单列，文字横排。以角色默认 256 × 256 的窗口为基准，建议每个团子宽 82、高 38 个逻辑像素，整行点击区高 44，行间空 4；整列高 188，垂直中心与角色窗口中心对齐。团子与角色轮廓之间留一小段空隙，以实际待机帧的透明留白微调，不能遮住脸、问候气泡或角色的拖动区域。
- **靠边时仍点得到。** 优先放右侧，剩余宽度不足就整列移到左侧，次序照旧；靠近屏幕顶底时仅调整菜单的纵坐标。根据角色所在显示器的工作区计算，覆盖任务栏、多屏负坐标和不同缩放。展开、收起都不挪动渚，也不改写已保存的位置。
- **已绘素材位置。** 四个按钮共用一张团子底图，仓库路径为 [nagisa-app/src/assets/quick_menu/dango_base.png](../nagisa-app/src/assets/quick_menu/dango_base.png)。已核对为 256 × 128 像素、8 位 RGBA 的透明 PNG。图中保留了团子轮廓和左上方高光，中央留白供界面叠加文字。接入时按等比缩放底图，分别着色并叠加「喂食」「打工」「学习」「游戏」；悬停、按下和键盘焦点由按钮样式呈现。
- **动效与键盘。** 默认短暂淡入，打开「减少动态效果」就直接显示。每个团子用带中文名称的按钮；键盘可用 Tab 按显示顺序移动、Enter 或空格进入，焦点轮廓在四种底色上均清楚。

## 四、分步实施

1. **复用现有轻点判定。** 在 [index.ts](../nagisa-app/src/index.ts) 的 `pet:finish` 确认是一次有效轻点后，由主进程根据当前菜单状态切换展开或收起。同步调整 [renderer.ts](../nagisa-app/src/renderer.ts) 的 `finishPointer` 和 [接口声明](../nagisa-app/src/pet-api.d.ts)，让渲染器只在「轻点展开」时调用现有问候逻辑。问候请求失败也不影响菜单。沿用同一个手势编号和点击阈值，避免一次松手被额外的 `onClick` 处理第二次。
2. **做一个贴着角色的轻量窗口。** 建议新增 `nagisa-app/src/quick-menu.ts`，由现有渲染入口按新页面标识加载。主进程首次展开时创建一个透明、无边框、不占任务栏的菜单窗口，以后复用。只给菜单设置边界和临时焦点；桌宠本体继续用原来的正方形窗口处理位置保存和指针捕获。显示前按当前角色位置、缩放和工作区算好布局，隐藏时整窗退出鼠标命中。Windows 下可用窗口形状限定四行点击区，特别验证团子之间的空隙能点到底下的应用。
3. **接通四个入口。** 在 [preload.ts](../nagisa-app/src/preload.ts) 暴露仅供菜单页调用的选择操作，主进程校验发送窗口、菜单仍可见、动作属于 `feed / bakery / study / game` 后再分发。一次选择即消费本次菜单；快速双击也只打开一次。已打开的手账应切回手账页并滚动到新目标，已有游戏窗口应恢复并置前。复用右键菜单的同一组路由，保持两种入口行为一致。
4. **处理焦点和窗口寿命。** 菜单失焦到其他应用时收起；焦点转到渚时，把收起交给本次角色手势，避免“失焦先收起、松手又展开”。启动拖动、显示右键菜单、关闭桌宠或切换穿透时统一收起。显示器拔插和角色缩放预览期间可直接收起，下次展开重新定位。对已隐藏或已销毁菜单发来的迟到点击直接忽略。
5. **构建与交付。** 从 v1.0.3 开发，功能验收后同步应用及锁文件版本。在 `nagisa-app` 中运行 `npm.cmd run typecheck` 和 `npm.cmd run release:windows`，使用生成的 v1.1.0 完整 Setup 复测。更新 README 的首次操作说明，在[更新记录](更新记录.md)填写实测结果、源码提交与最终安装包校验值。

## 五、验收用例

| 场景 | 怎么测 | 通过标准 |
| --- | --- | --- |
| 对照草图 | 把渚拖到屏幕中央，轻点一次、再点一次 | 第一次在右侧看到按指定次序排列的四个团子，渚留在原位置；第二次收起，菜单无残留点击区。 |
| 四个目的地 | 分别从手账关闭、已打开其它标签两种状态点四个团子 | 喂食到背包，打工到帮工，学习到温习，游戏到小游戏。手账和游戏各自复用窗口；导航本身不扣食物、不扣精力、不新建活动。 |
| 问候和拖动回归 | 用今天尚未问候的测试档轻点，反复开合；再分别横移 5、6 个逻辑像素后松手 | 首次问候遵守原奖励规则，重复开合不会多发好感。5 像素仍按轻点处理，6 像素进入原拖动姿势且不会展开菜单。 |
| 忙碌时访问 | 帮工期间点「学习」，已有一局游戏时再点「游戏」 | 手账展示当前活动与倒计时；小游戏回到原局。活动结算和游戏进度正常。 |
| 靠边与缩放 | 右侧贴边、上下角、多屏不同 DPI，以及角色 100% 和 150% 缩放分别展开 | 右侧不足时四项完整翻到左侧，标签可读、命中位置与显示一致；关闭后重启，渚的位置不变。 |
| 收起与穿透 | 点击外部窗口、团子间隙、按 Esc、右键渚；再测试隐藏、找回、鼠标穿透和全屏隐藏 | 外部点击正常传递；右键菜单可用；隐藏或穿透时无悬空团子。再次轻点可正常打开。 |
| 键盘与减少动态 | 展开后按 Tab、Enter、空格、Esc，切换「减少动态效果」后重试 | 焦点顺序与视觉顺序一致，每次只响应一个操作；减少动态时无进场动画，四项仍可用。 |
| 最终安装包 | 用 v1.0.3 存档升级到 v1.1.0，在安装版连续展开和收起 20 次，然后打开四项 | 四项均可达，托盘无重复入口，窗口数不随开合次数增加。原存档、桌面偏好和拖动位置均可续用。 |
