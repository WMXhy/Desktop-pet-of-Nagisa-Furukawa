# 第九次开发指南 · 让渚记住与你相处的日子

**本次完成线**：从好感 29 的测试档开始，轻点渚一次。好感变为 30，称号从「初识」变为「熟悉」，手账新增一条关系记录。当天再点、关闭手账或重启，仍然是 30，记录只有一条。继续达到 80 可听渚练台词，达到 150 可看到专属待机动作，并重看纪念对话。

接续[第八次开发指南](08-第八次开发指南.md)。当前工程已有 v5 存档，喂食、活动和小游戏都会结算好感；角色轻点目前播放问候。本次把这些入口接入同一份关系记录，完成总方案阶段四的最后一项。

## 2. 四档关系与实际体验

| 好感 | 称号 | 玩家看到的变化 |
|---|---|---|
| 0～29 | 初识 | 显示当前点数与距离 30 的差值，沿用简短问候 |
| 30～79 | 熟悉 | 解锁放学、面包店话题。例：“今天给面包袋打了个小结，你觉得好看吗？”保留原有学习点专属台词 |
| 80～149 | 信赖 | 手账记录原创小事件「排练前的一句话」，出现「听她练一句台词」按钮。例：“如果我中途忘词，你可以再给我一个开始的手势吗？” |
| 150～300 | 亲密伙伴 | 空闲时偶尔出现亲密待机动作，手账解锁可重看的原创纪念对话。例：渚说“第一次排练时，我连第一句都念得很轻。”玩家回应“今天我听清楚了。”渚说“那，明天的第一句也念给你听。” |

每个新话题先备 3 条短句，挑选时避开上一条。熟悉后的主动问好沿用总方案「主动说话默认关」的约定：本次先接通**玩家轻点触发**的话题，把主动触发留给设置与免打扰阶段。关系记录可随时重看；听台词和重看对话均不耗精力、不加好感。

## 3. 存档从 v5 升为 v6

在 [care.ts](../nagisa-app/src/care.ts) 中继续让 `affection` 作为点数来源，称号和距离下一档的数值实时计算。建议新增两类持久数据：

- `lastGreetingDay: string | null`：记录上一次已处理“当日首次轻点”的本机日期，与现有 `localDay()` 使用相同口径。每日好感已满时，首次问候仍记下日期，实际收益显示 0。
- `relationshipLog`：最多三条，以稳定 ID（`familiar`、`trusted`、`companion`）去重。每条保存 `id` 和 `unlockedAt: number | null`。新事件用提交时的 UTC 毫秒；从旧档补录的事件用 `null`，手账显示“从旧存档继承”。台词和称号放本地内容表，可在后续改文案。

在 [care-store.ts](../nagisa-app/src/care-store.ts) 中先把当前带 `ownedToys` 的结构保留为显式 `CareV5`，再扩展 `LegacyCare` 和当前版本。现有 `readSave()` 以 `version === careVersion` 识别最新档，升级后须显式保留 v5 分支。v1～v4 沿用既有迁移，v5 保留两件玩具的真实状态；最后根据原好感补齐**所有已达**门槛，不补发点数、不弹首次事件。主档和备份走同一转换；v6 校验日期、事件 ID、时间及唯一性。活动截止时间、奖励快照、小游戏中途退出规则和每日累计原样保留。

**迁移检查点**：打开一份好感 100、已买玩偶的 v5 测试档。应是「信赖」，有 30、80 两条继承记录，好感仍为 100，玩偶仍可用。再次启动时记录数量不变。

## 4. 把跨档检测放在一次成功提交里

可在 `src/relationship.ts` 集中定义阈值与纯函数。下面的函数可以独立验证，既处理恰好达到，也处理一次加 2 点跳过边界：

```ts
export const milestones = [
  { id: 'familiar', min: 30, title: '熟悉' },
  { id: 'trusted', min: 80, title: '信赖' },
  { id: 'companion', min: 150, title: '亲密伙伴' },
] as const;
export type MilestoneId = typeof milestones[number]['id'];

export function newMilestones(before: number, after: number, recorded: readonly MilestoneId[]) {
  return milestones.filter(m => before < m.min && after >= m.min && !recorded.includes(m.id));
}
```

1. **统一结算位置。** [care-runtime.ts](../nagisa-app/src/care-runtime.ts) 的 `commit()` 是喂食、活动到期和游戏完成的共同路径。先取 `store.snapshot()` 中提交前的状态，对比候选状态中的**实际好感**，生成新增记录，将点数、每日累计和事件一次写进同一份存档。继续由 store 更新修订号。
2. **成功后再提示。** 扩展 `CareChange` 携带本次新增的事件 ID，保留现有的活动完成与游戏结果。写盘失败保留旧状态，重试成功只生成一次记录。程序启动时补结算离线活动也要入账；沿用启动静默结算，把“记录事件”和“显示气泡”分别控制。
3. **避免两条气泡争抢。** 喂食、帮工或游戏结果与升级同时出现时，先播当前动作，可在同一反馈末尾追加“关系已升为信赖”，或让玩家在手账看到新条目。角色隐藏期间以手账为准。打开手账、读取快照、动作重播均不创建事件。
4. **继续用现有日限。** 所有好感变更都通过现有 `gainAffection()`，每个本机自然日最多 12，累计最多 300。检查的是限幅后的真实值。例如 79 点、当日已获 11 点，吃红豆面包实际只加 1 点，仍会准确触发 80 点事件。好感到顶时继续正常结算饱食、心情或工资。

## 5. 轻点问候、信赖互动与亲密待机

| 修改位置 | 实施方法 | 检查点 |
|---|---|---|
| [index.ts](../nagisa-app/src/index.ts)、[renderer.ts](../nagisa-app/src/renderer.ts) | 保留现有 `pet:finish` 的点击/拖动判别。角色端在 `greet.current` 确认可播放问候后，向主进程发送一次玩家问候请求；渲染端加约 2 秒短冷却，拖动、自动气泡、点手账按钮都不算问候。 | 同一天连续点击可看到短句，但只首次有收益。拖动再松手后，当天首次加点机会仍在 |
| `care.ts`、`care-runtime.ts` | 增加 `greetToday`。使用主进程本机日期；若已领取，当作普通问候返回，跳过养成写盘。首次通过原 `apply()` 同步保存日期与 `gainAffection(state, 1, day)` 的结果。并发请求在实际提交时重新检查日期；失败不能占用当日机会。 | 23:59 与次日 00:01 各能获得一次；同日退出、重启不会再加 |
| [preload.ts](../nagisa-app/src/preload.ts)、[pet-api.d.ts](../nagisa-app/src/pet-api.d.ts) | 给角色窗口暴露窄接口 `greetToday()`，给手账暴露 `listenToLine()`。主进程按来源窗口和主 frame 检查。听台词时重新核对好感 ≥80、角色可见、空闲且无小游戏；参考已有抱玩偶入口发送一次角色事件。 | 79 点在界面和主进程都无法启动；80 点时即使学习点为 0、没买舞台，也能听一次 |
| `renderer.ts / Pet()` | 信赖互动复用 `rehearse` 四帧和现有 `interact()`；点播完恢复当前姿势。为亲密待机增加 `idle_close` 序列，在 `restorePose()` 的空闲分支低频插入，例如每第三次原定眨眼机会播放一次，结束后恢复正常眨眼。活动、局中、进食、抱玩偶或隐藏时让位。 | 可在约 20 秒内观察到专属姿势；快照刷新不重置计数，亲密动作不插入正在播的交易或游戏反馈 |

**问候台词的衔接**：现有角色在学习点达到 20 时可说学习专属语句。把已有句子与当前称号解锁的句子放入同一可选列表。玩家主动点播「听她练一句台词」是一次短表演，与耗精力的 5 分钟「朗读排练」、需要舞台的「台词接龙」分别保留自己的入口。

## 6. 手账关系页

在 `Journal()` 现有 `journalTabs` 中加「关系」页，沿用 [care-snapshot.ts](../nagisa-app/src/care-snapshot.ts) 的快照。实现顺序如下：

1. **页首**：显示“信赖 · 84 / 300”和“距离亲密伙伴还差 66 点”；150 点以后改为“全部关系称号已解锁”。显示今日好感时，若 `daily.day` 已不是今天，展示 0 / 12。手账跨午夜保持打开时，也应刷新这项展示。
2. **里程碑列表**：按 30、80、150 展示。锁定项给差值；解锁项显示到达日期或继承标记，可展开其原创内容。空记录的新档显示下一目标，不放虚构的首次相遇日期。
3. **可执行互动**：信赖起提供「听她练一句台词」；亲密伙伴提供「重看纪念对话」。重看在手账内完成，隐藏角色时照常可读。两项都不能影响学习、当日问候、游戏或玩具状态。

## 7. 试玩与验收

在项目根目录运行。每个边界用例可用单独的内存夹具或独立测试档；编辑测试 JSON 前先完整退出桌宠。构造 v6 档时，已达旧门槛应当已有对应记录。

```powershell
Set-Location '.\nagisa-app'
$env:NAGISA_TEST_DATA = Join-Path $env:TEMP ('nagisa-relationship-' + [guid]::NewGuid().ToString('N'))
npm.cmd run typecheck
npm.cmd start
```

| 用例 | 操作 | 通过标准 |
|---|---|---|
| 首次与重复问候 | 当日已获 0 点、好感 29，先拖动后轻点；再连点、重启 | 拖动保持 29；轻点到 30，今日累计 1，熟悉记录恰好一条；其余操作不再加点 |
| 多种入口跨线 | 用不同夹具从 29 喂一个小面包、从 79 完成一局游戏、从 149 离线完成一次温习 | 分别解锁 30、80、150；各一条记录。离线所得在手账可见，重复打开不播首次事件 |
| 日限与日期 | 79 点且今日已获 11，喂红豆面包；另测今日已获 12 时首次问候、传入下一本地日再问候 | 前者实际到 80；日满只问候不加点；次日首点可加 1。到 300 时仍不会溢出 |
| 信赖权限 | 同样设学习点 0、无舞台，分别用 79 和 80 点调用听台词；在忙碌时再试 | 79 拒绝，80 空闲时播一遍，忙碌时提示稍后；精力、币数、学习点和好感均不变 |
| 亲密待机 | 分别用 149、150 点且没有玩偶的档在桌面等待，再开始帮工、隐藏、找回 | 只有 150 在空闲时显示亲密姿势；忙碌时显示活动动作；纪念对话可反复看 |
| 写盘失败重试 | 用独立测试目录，在 29 点首次问候前阻止一次主档临时文件替换，恢复后再点击 | 首次失败不显示升级，点数和问候日期未提交；重试后到 30 并产生一条记录 |
| 迁移和恢复 | 分别测 v1～v5 有效档及从有效旧备份恢复；选一个 150 以上的档连续重启两次 | 旧进度保留，达到的称号补记为继承，无虚构日期；最多三条记录。原有学习、商店和两件玩具仍按原条件可用 |

**交付时走一遍真实入口**：桌面轻点触发熟悉 → 打开手账查看日期 → 达到信赖后听渚练台词 → 解锁亲密待机并重看纪念对话。确认重启后称号、记录和当日问候状态一致，即可进入长期使用与设置界面的开发。
